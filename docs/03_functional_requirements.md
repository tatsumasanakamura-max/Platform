# 機能要件

## 1. 追跡方法

各要件は目的ID、実装要素、テストIDで追跡する。詳細な定義形式は [07_form_definition.md](07_form_definition.md)、ルールは [08_rule_engine.md](08_rule_engine.md) を参照する。

## 2. 申込者機能

| ID | 要件 | 受入条件 | 目的 |
|---|---|---|---|
| FR-APP-001 | 公開済みの銀行・商品・版に対応する申込フォームを開始できる | 未公開版は開始不可。開始後は版が固定される | OBJ-02,03 |
| FR-APP-002 | 本人情報を入力できる | 定義された項目、順序、選択肢、補助文が表示される | OBJ-03,06 |
| FR-APP-003 | 勤務先・収入情報を入力できる | 条件に応じた表示・必須が反映される | OBJ-03,06 |
| FR-APP-004 | 契約情報を入力できる | 商品条件に応じた項目と選択肢を表示する | OBJ-03 |
| FR-APP-005 | 単項目チェックを指定タイミングで実行する | `onBlur`、`onSectionNext`、`onSubmit` の定義どおりに同じ結果となる | OBJ-04,06 |
| FR-APP-006 | 回答に応じて項目の表示・必須状態を変更する | 同一入力・同一版では常に同じ状態となる | OBJ-02,04 |
| FR-APP-007 | 回答に応じて後続セクションを分岐する | 到達不能・循環が公開前に検出される | OBJ-02,04 |
| FR-APP-008 | 入力途中の回答を保存・再開できる | 保存範囲、期限、本人確認方法はOQ-05確定後に受入条件を補完 | OBJ-06 |
| FR-APP-009 | 送信前に回答、重要事項、同意文面を確認できる | 同意版と時刻が監査記録に残る | OBJ-04 |
| FR-APP-010 | 有効な申込を送信し結果を受け取る | サーバー側再検証後のみAPIスタブへ送信する | OBJ-04 |
| FR-APP-011 | エラー時に回答を失わず復帰できる | 再試行可否と問い合わせ導線が明確で二重送信しない | OBJ-06 |
| FR-APP-012 | 進捗と残りの目安を認識できる | 分岐後も到達可能セクションを基に表示する | OBJ-06 |

## 3. 定義・バージョン管理

| ID | 要件 | 受入条件 | 目的 |
|---|---|---|---|
| FR-DEF-001 | 定義を `bank_id/product_id/form_version` で一意に識別する | 組合せ重複を拒否する | OBJ-03,04 |
| FR-DEF-002 | 項目追加・削除・表示名・順序・必須・選択肢を定義できる | コード変更なしでUIに反映される | OBJ-02,03 |
| FR-DEF-003 | チェック有無・内容・タイミングを定義できる | 許可済み演算子のみ使用可能 | OBJ-02,04 |
| FR-DEF-004 | 表示・必須・セクション分岐条件を定義できる | 参照、型、循環、安全性を公開前検証する | OBJ-02,04 |
| FR-DEF-005 | 審査APIの項目マッピングと変換を定義できる | 契約テストを通過しない版は公開不可 | OBJ-02,03 |
| FR-DEF-006 | ブランド・文言・同意文を差分定義できる | 同意文は承認者と版を記録する | OBJ-03,04 |
| FR-DEF-007 | 定義をドラフト、レビュー中、承認済み、公開、廃止で管理する | 状態遷移と操作者が監査可能 | OBJ-04 |
| FR-DEF-008 | 公開済み版を不変にする | 修正は新しい版としてのみ公開可能 | OBJ-04 |
| FR-DEF-009 | 版間差分と影響範囲を表示する | 項目、ルール、経路、API、テストの差分を列挙する | OBJ-02,05 |
| FR-DEF-010 | 申込開始時の版を完了まで保持する | 移行は明示ポリシーがない限り行わない | OBJ-04 |
| FR-DEF-011 | 共通定義を基に商品・銀行差分を構成できる | 解決済み定義を公開時に凍結する | OBJ-03 |
| FR-DEF-012 | 定義から人間可読仕様とトレーサビリティを生成する | 要件ID・ルールID・テストIDが相互参照できる | OBJ-04,05 |

## 4. AI支援・品質ゲート

| ID | 要件 | 受入条件 | 目的 |
|---|---|---|---|
| FR-AI-001 | 要件文と項目一覧から構造化候補を生成する | 未確定事項を仮定として明示し、無断で業務要件化しない | OBJ-01 |
| FR-AI-002 | 変更要求の影響分析を生成する | 影響する定義、ルール、API、テスト、文書を提示する | OBJ-02,05 |
| FR-AI-003 | 定義・コード・テスト・文書の変更候補を生成する | 生成元と生成記録を付す | OBJ-01,04 |
| FR-AI-004 | 不整合を検出する | 仕様、定義、ランタイム契約、テストの差異を報告する | OBJ-04 |
| FR-AI-005 | 生成物を自動検証する | 検査結果が全て成功しない限り承認へ進めない | OBJ-04 |
| FR-AI-006 | 人間が差分を承認・棄却・修正できる | 判断者、時刻、理由を記録する | OBJ-04,05 |
| FR-AI-007 | 生成履歴と人間修正量を記録する | MET-05、MET-06を再計算できる | OBJ-01,05 |

## 5. 連携・監査・計測

| ID | 要件 | 受入条件 | 目的 |
|---|---|---|---|
| FR-INT-001 | 内部回答を審査API契約へ変換する | 変換前後を契約テストし、機微値はログへ残さない | OBJ-03,04 |
| FR-INT-002 | 認証方式を銀行アダプターで切替可能にする | PoCでは2方式のモックで差分を証明する | OBJ-03 |
| FR-INT-003 | 冪等キーで二重申込を防止する | 同一キーの再送は同一結果を返す | OBJ-04 |
| FR-AUD-001 | 定義作成・承認・公開・廃止を監査記録する | 誰が、いつ、何を、なぜ変更したか復元可能 | OBJ-04,05 |
| FR-MET-001 | 工程イベントを計測する | 要件確定、生成、レビュー、自動テスト、公開の時刻を持つ | OBJ-01,02 |
| FR-MET-002 | UXイベントを計測する | セクション閲覧・エラー・離脱・完了を匿名セッション単位で記録する | OBJ-06 |
| FR-MET-003 | 評価用証跡をエクスポートする | 指標の入力レコードと計算式を追跡できる | OBJ-01〜06 |

## 6. 未確定業務項目

具体的な氏名、住所、勤務、年収、希望限度額等の項目一覧、許容値、審査マッピング、同意文、保存再開条件は未確定であり、本書では金融業務要件として確定しない。優先度と期限は [13_risks_and_open_questions.md](13_risks_and_open_questions.md) に置く。
