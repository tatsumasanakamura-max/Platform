# 機能要件

## PoC-1必須

| ID | 要件 | 受入条件 | 目的 |
|---|---|---|---|
| FR1-001 | 仮想銀行・商品・版でフォームを開始する | `bank_id/product_id/form_version` を設定から取得 | OBJ-01,05 |
| FR1-002 | 本人・勤務先・契約の15〜25項目を表示する | 項目はすべて `sections[].fields[]` に格納し、型・表示名・順序・選択肢を反映 | OBJ-01,02 |
| FR1-003 | 固定requiredと条件付きrequiredを定義する | 非表示なら任意、ルール参照があればルール結果、なければ固定値を使う | OBJ-02,07 |
| FR1-004 | 名前付き項目バリデーターで単項目チェックを行う | 許可typeだけを指定タイミングで評価し、error_codeを返す | OBJ-04,07 |
| FR1-005 | 固定visibleとvisibilityルールで表示状態を決める | ルール参照があればルール結果、なければ固定値を使い、非表示値は送信しない | OBJ-03,04 |
| FR1-006 | 基本遷移と条件付きnavigationを分離する | 条件一致時はルール結果、一致なしはdefault、複数同時成立は禁止 | OBJ-03,07 |
| FR1-007 | 確認画面と完了画面を表示する | 送信はAPIスタブで完了し実与信を行わない | OBJ-01 |
| FR1-008 | フォーム定義をSchema・静的検証する | 構造、参照、許可値、遷移、条件重複の不正でbuild失敗 | OBJ-02,04 |
| FR1-009 | 同じ条件ルール・バリデーター実装をブラウザとNode.jsで使う | 同一テストベクトルの結果一致 | OBJ-04 |
| FR1-010 | 本番利用不可を表示する | 開始画面とREADMEで確認可能 | OBJ-01 |
| FR1-011 | Firebase Hostingへ必要時に公開する | build/test合格後だけ手動デプロイ | OBJ-01 |
| FR1-012 | 作業記録を残す | 指示、時間、生成、人間修正、テスト、問題、改善を記録 | OBJ-02,06 |
| FR1-013 | バリデーションタイミングを設定する | `onBlur/onSectionNext/onSubmit` だけを指定可能 | OBJ-04,07 |
| FR1-014 | 条件ルールと単項目バリデーターを分離する | 形式・長さ・範囲はvalidator、回答条件・項目関係はvalidationルール | OBJ-02,04 |
| FR1-015 | エラーコードと表示文を分離する | validator/validationルールはerror_code、UIは単純な文面定義を使用 | OBJ-02,07 |

## 評価責務

- 固定required／requiredルール: 項目を入力する必要があるか。
- named validators: 単一項目の形式、文字数、数値範囲が正しいか。
- validationルール: 回答条件または複数項目の関係による業務的チェック。
- ルートnavigation: 基本遷移と条件ルール参照。
- navigationルール: 条件一致時の遷移先だけを返す。

任意正規表現、JavaScript式、任意コードはフォーム定義へ記載できない。

## PoC-2候補

| ID | 要件 |
|---|---|
| FR2-001 | 項目削除、順序変更、同意文変更を検証する |
| FR2-002 | 2商品目と別銀行のブランド・文言差分を追加する |
| FR2-003 | 商品・銀行別APIマッピング差分を追加する |
| FR2-004 | 合成データだけで簡易途中保存・再開を行う |
| FR2-005 | 必要ならAuthenticationを導入する。電話認証は使わない |
| FR2-006 | 必要ならFirestoreへ定義・セッション・評価イベントを保存する |
| FR2-007 | 必要ならFunctionsで最終検証、冪等受付、APIスタブ送信を行う |
| FR2-008 | 簡易UXイベントを記録する |

## Firebase利用時の共通要件

- FR-FB-001: Firestoreは定義を1回取得後キャッシュし、不要なリアルタイムリスナーを使わない。
- FR-FB-002: Functionsを使う場合、入力1項目ごとに呼ばず、最終検証など限定用途にする。
- FR-FB-003: ローカル開発と自動テストではEmulator Suiteまたはモックを使う。
- FR-FB-004: 公開環境へ保存する場合も合成データだけとし、Security Rulesをテストする。

管理画面、Definition Registry、多人数承認、本格監査はPoC-1要件ではない。
