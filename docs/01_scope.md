# スコープ

## PoC-1: 最小方式検証

| ID      | 対象                                                            |
| ------- | --------------------------------------------------------------- |
| SCP1-01 | 仮想銀行1行・仮想カードローン1商品                              |
| SCP1-02 | 本人、勤務先、契約の代表15〜25項目                              |
| SCP1-03 | 必須・任意、選択肢、単項目チェック、3〜5件の条件分岐            |
| SCP1-04 | セクション移動、確認画面、完了画面、スマートフォン対応          |
| SCP1-05 | JSONまたはYAMLのフォーム定義とJSON Schema v0                    |
| SCP1-06 | 限定ルール評価、Unit/E2Eテスト、ブラウザまたはローカルAPIスタブ |
| SCP1-07 | Firebase Hostingへの必要時デプロイ                              |
| SCP1-08 | GitHub上のコード、定義、テスト、文書、worklog                   |
| SCP1-09 | 必要性を確認した場合のみFirestore、Functions、App Check等を追加 |

まず静的フォームとローカルスタブで縦切りを完成させる。FirestoreとCloud FunctionsはPoC-1の必須条件ではない。

## PoC-2: 柔軟性・横展開検証

| ID      | 対象                                   |
| ------- | -------------------------------------- |
| SCP2-01 | 商品変更シナリオと2商品目              |
| SCP2-02 | 別銀行を模したブランド・文言差分       |
| SCP2-03 | 条件分岐・APIマッピング差分            |
| SCP2-04 | 合成データによる簡易な途中保存・再開   |
| SCP2-05 | UXイベント計測                         |
| SCP2-06 | 必要性が確認できた場合だけ簡易設定画面 |

PoC-2へはPoC-1完成と振り返り後に進む。

| OOS-06 | SMS認証、常時稼働処理、高頻度ポーリング、大量トリガー               |
| OOS-07 | 本格的な申込永続化、AI生成台帳アプリ                                |

## 制約

Blazeプランを使うが無料利用枠内・月額0円を目標とする。通常開発はローカルとEmulator Suiteを優先し、クラウドデプロイを主要な節目に限定する。課金可能性のあるサービス追加は人間が事前判断する。

## PoC-1B追加スコープ

PoC-1の方式検証を補助する単独利用の[フォーム要件定義スタジオ](form-studio/overview.md)を対象に含める。JSON Import/Export、定義編集、共通Runtime Preview、軽量検証、Undo/Redo、localStorage、属性単位差分、派生Markdownまでとし、Firebase保存、認証、共同編集、承認、公開管理は対象外のままとする。
