# PoC評価計画

## 評価の位置づけ

開発者1名による自己評価であり、厳密な対照実験や統計的な一般化は行わない。本人の過去経験または手動作業の参考値と比較し、次段階へ進む価値があるか判断する。

## KPI

| ID | 指標 | 記録方法 | 目的 |
|---|---|---|---|
| KPI-01 | 初期プロトタイプ完成までの実作業時間 | worklogの開始・終了・除外時間 | OBJ-01 |
| KPI-02 | 変更要求から動作確認までの時間 | 変更別worklog | OBJ-03 |
| KPI-03 | コード変更なしで対応できた変更数 | Git差分を定義のみ／コードありに分類 | OBJ-03 |
| KPI-04 | Codex初稿をそのまま／軽微修正で採用できた割合 | 採用区分と人間修正の要約 | OBJ-02 |
| KPI-05 | 自動テストで発見した不具合数 | テスト結果と問題欄 | OBJ-04 |
| KPI-06 | 人間レビューで発見した重要な誤り | reviewメモ | OBJ-02 |
| KPI-07 | 変更後の回帰テスト成功率 | 成功テスト数／全回帰テスト数 | OBJ-04 |
| KPI-08 | 2商品目追加の実作業時間 | PoC-2 worklog | OBJ-05 |
| KPI-09 | 別銀行模擬の実作業時間 | PoC-2 worklog | OBJ-05 |
| KPI-10 | 一定期間後にCodexが文書から作業を再開できるか | 新規会話で再開し不足情報を記録 | OBJ-06 |
| KPI-11 | スマートフォンでの申込完了時間 | 手動または少人数モニター | OBJ-07 |
| KPI-12 | 入力エラー数・迷った箇所 | 観察メモ | OBJ-07 |

## 工数区分

| 区分 | 例 |
|---|---|
| BASE | 開発環境、CI、Firebase、Schema、共通ランタイム |
| PRODUCT1 | 初期商品定義、文言、代表テスト |
| CHANGE | 項目・選択肢・必須・分岐の変更 |
| EXPAND | 2商品目、別銀行模擬 |

BASEを商品追加・変更工数に混ぜない。

## 記録形式

MarkdownまたはCSVで、作業内容、Codex指示、開始・終了、生成内容、人間修正、テスト結果、問題、次回改善を記録する。Gitコミットを紐づけるが、改ざん防止された評価証跡は作らない。

## 判定

PoC-1完成後、動作、回帰、変更容易性、実作業時間、コスト見込み、過剰設計の有無を振り返る。厳密な効果証明ではなく、PoC-2へ進む、PoC-1を改善する、中止するの判断材料とする。
