# AI Native開発方式

## 最低成立条件

Codexが要件整理、設計、定義・コード・テスト・文書の変更、影響分析、自己レビューを連続して行い、人間が目的・制約・最終判断を担う。生成物はGit差分と自動テストで検証でき、AIなしでも申込実行は決定的に動作する。

## 役割

| ID | Codex | 決定的プログラム | 人間 |
|---|---|---|---|
| AIN-01 | 曖昧点・仮定・実装案を提示 | Schema検証 | 目的と要件を確定 |
| AIN-02 | 定義、コード、テスト、文書を同時更新 | build、Unit、E2E | 差分と重要誤りをレビュー |
| AIN-03 | 変更影響と回帰候補を提示 | 参照・型・テストで確認 | 採用・修正・棄却を判断 |
| AIN-04 | 自己レビューと別ターンレビューを支援 | 同一入力で同一結果 | コミット・公開を決定 |
| AIN-05 | 申込判定時は使用しない | 表示、必須、検証、遷移 | PoC結果を解釈 |

## 検証手段

Gitで差分・コミット・定義ハッシュを追跡し、自動テストで構文、ルール、代表経路、回帰を確認する。仮定と再開手順は文書へ、指示・時間・生成内容・人間修正・問題・改善点は `docs/worklogs/` へ簡易記録する。本格的な生成台帳や多人数承認システムは作らない。

## 禁止境界

AI推論を表示・必須・入力妥当性・遷移・申込受付の決定経路へ入れない。実在人物・実在銀行の機密情報をCodexへ入力しない。課金可能性のあるFirebaseサービスをCodex判断だけで有効化しない。
