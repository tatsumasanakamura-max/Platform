# UI/UX設計原則

## 目的

PoC-1のUIは「Calm Trust／静かな信頼」を共通概念とし、豪華さではなく、迷いにくさ、エラー回復、安心できる説明、アクセシビリティで品質を示す。本番銀行サービスではなく、仮想銀行・仮想商品と合成データだけを扱う技術検証である。

## 原則

| ID        | 原則               | 実装判断                                                                         |
| --------- | ------------------ | -------------------------------------------------------------------------------- |
| UX-DS-001 | 利用者中心         | 一画面の目的を一つにし、現在地、次の操作、戻り方を明示する                       |
| UX-DS-002 | 離脱防止           | 入力値を戻る操作で失わず、エラーから修正箇所へ直接移動できる                     |
| UX-DS-003 | 説明責任           | 説明を隠して完了率を上げない。本番利用不可、非審査、合成データ限定を反復表示する |
| UX-DS-004 | ダークパターン禁止 | 借入れを急がせる表現、偽の希少性、初期選択による誘導を使わない                   |
| UX-DS-005 | モバイルファースト | 390pxを主基準、320pxを下限とし、44px以上の操作領域を確保する                     |
| UX-DS-006 | 回復可能性         | エラーは原因と修正方法を示し、入力者を責めない                                   |
| UX-DS-007 | 決定的UI           | 表示、必須、検証、遷移はフォーム定義と決定的TypeScriptから導出する               |
| UX-DS-008 | 必要最小限         | PoC-1で使う部品だけを整備し、テーマ切替や管理画面を先に作らない                  |

## 完了率の扱い

完了率を上げるために、重要説明を弱めたり、任意項目を必須に見せたりしない。所要時間は根拠が得られるまで「検証後に更新」と表示する。UX評価は[アクセシビリティ基準](accessibility.md)と既存の[UX原則](../05_ux_principles.md)を併用する。
