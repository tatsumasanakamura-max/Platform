# UX原則

## 目標

必要な入力と説明を保ちながら、スマートフォン利用者が迷わず完了できるプロトタイプを作る。完了率を上げるために説明や同意を弱める設計は行わない。

| ID | 原則 | PoCでの確認 |
|---|---|---|
| UX-001 | 1画面の情報量を抑え、本人・勤務先・契約へ分ける | 完了時間、迷った箇所 |
| UX-002 | 進捗、必要情報、次の操作を明示する | 操作観察 |
| UX-003 | 入力形式と例を入力前に示す | 入力エラー数 |
| UX-004 | エラーの原因と直し方を項目近傍に示す | エラー回復時間 |
| UX-005 | 条件に合わない項目を表示せず送信しない | 分岐テスト |
| UX-006 | 戻る操作で入力を失わない | 代表経路E2E |
| UX-007 | 適切なモバイルキーボードと十分なタップ領域を使う | 実機確認 |
| UX-008 | ラベル、フォーカス、読み上げ順、色以外の手掛かりを持つ | axe・手動確認 |
| UX-009 | 仮想商品・合成データ・本番利用不可を明示する | 開始画面確認 |
| UX-010 | 計測する場合も入力値をイベントへ含めない | イベント確認 |

## 簡易ユーザーテスト

開発者本人が代表シナリオを実行する。可能であれば家族・知人など少人数モニターに、合成データで操作してもらう。申込完了時間、入力エラー数、戻る操作、迷った箇所、理解できなかった文言を記録する。標本が小さいため統計的な一般化はしない。

## PoC-1とPoC-2

PoC-1ではスマホ主要導線、エラー、分岐、確認・完了に集中する。途中保存、詳細イベント分析、ブランド比較はPoC-2で必要性を判断する。
